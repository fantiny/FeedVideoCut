# 打标侧改进待办（来自 FeedVideoMake 制作侧实战反馈）

> 来源：2026-09-07 FeedVideoMake 自动混剪多轮问题排查。
> 每条包含：现象 → 对制作的影响 → 建议的打标改进 → Make 侧已有的临时缓解。
> 优先级：P0 = 直接导致成片质量问题；P1 = 明显降低匹配质量；P2 = 债务/一致性。

## P0-1 ✅ 已完成（2026-09-07）「是否有字幕」检测

- **现象**：素材 v1–v10 均为带原广告花字的成片（如「现在只要7块9一盒」），检索/绑定/合成无从知晓。
- **影响**：成片出现两套字幕叠加；Make 只能靠 crop/reposition 兜底。
- **建议打标改进**：
  - L1.5 新增检测器：底部字幕带（68–95% 高度）边缘密度比（Make 侧已有参考实现 `feedcut_common.image_subtitle_band_score`，可直接移植），输出列 `是否有字幕`（是/否）+ `字幕位置`（bottom/top/none）。
  - 导出索引新增列：`是否有字幕`、`字幕位置`。**Make 侧已在 `score_row_for_slot` 预留打分钩子**（`caption_conflict.strategy=avoid_tagged` 时 `是` -0.4 / `否` +0.25），列一到位即生效。

## P0-2 ✅ 已完成（2026-09-07）行为标签重写（视觉优先 + 进食证据）

- **现象**：行为列几乎只有「摇尾/人物讲解」，而素材真实包含进食、舔碗、等待投喂等；`进食证据` 列 162/162 全是「否」。
- **影响**：「看它吃得多香」曾被配上产品特写；LLM 绑定只能依赖失真标签推理。
- **建议打标改进**：
  - L2 行为规则重写：进食类行为（大口进食/舔碗/第一口/凑近闻/等待投喂/递碗投喂）应基于 YOLO 物体（dog+bowl 同框）+ 运动方向 + 时序规则，而非单一姿态判断。
  - `进食证据` 列真正落地：dog|cat 与 bowl/food 同框且持续 ≥0.5s → 是。
  - 每条行为附 confidence，低于阈值标 `pending` 而不是猜一个。
- **Make 临时缓解**：LLM 语义绑定阶段（bind_shots）用物体描述兜底推理。

## P0-3 ✅ 已完成（2026-09-07）音频人声检测（音节调制 VAD）

- **现象**：素材带人声解说，但 `音频质感` 未标出；Make 的 `force_mute_if_audio_texture_any: [人声讲解]` 因此失效。
- **影响**：成片原声人声与新配音重叠。
- **建议打标改进**：L2 音频层接 VAD/说话人检测（如 silero-vad + 声纹分类），输出 `音频质感` 增加 `人声解说` 标签；可同时输出 `人声时间段`。
- **Make 临时缓解**：hybrid 模式默认全静音原声（`role_mix: mute`）。

## P1-4 二级分类 41% 为 V99_待分类

- **现象**：67/162 条无法归类。
- **影响**：按类目选片（evidence→产品特写/工艺）覆盖面缩水。
- **建议**：补分类规则（V03_进食特写 等类目定义落地到规则），或用 CLIP/VLM 对 V99 兜底归类并列 `分类置信度`。

## P1-5 ✅ 部分完成（2026-09-07）新增「语义描述」中文字段（规则组合 + LLM 精修）

> 原「画面主体描述」仍为英文 YOLO 词表，保留作原始信号；中文语义描述已落 `语义描述` 列。

- **现象**：值为 `person, dog, bowl` 一类物体罗列，无动作/场景语义。
- **影响**：LLM 语义绑定只能靠猜测（曾把产品+手误判为「狗在进食」）。
- **建议**：输出中文名词短语 + 简单动作短语（如「金毛低头吃碗里的鲜粮」）；或直接接一次轻量 VLM caption。该字段是 LLM 绑定质量的上限所在。

## P1-6 犬种/主体、主体角色枚举混乱

- **现象**：同列混用 `狗/人物/产品/场景/人物+狗` 等自由文本。
- **建议**：定义枚举（犬种表 + 主体角色表），打标输出限定枚举值，便于过滤与统计。

## P2-7 material_id 基于绝对路径哈希

- **现象**：`material_id = sha1(绝对路径)`；工程已迁移目录，同批视频重打标会生成全新 ID，hub 出现重复条目。
- **建议**：改为 `sha1(相对工作区根路径)` 或文件内容哈希（size+mtime+时长），保证跨机器/跨目录稳定。**迁移后若重打标本批素材，旧 hub 条目需清理或合并。**

## P2-8 「已用次数」无回写机制

- **现象**：索引有 `已用次数` 列但无人维护（契约 v1 禁止 Make 写回 hub）。
- **建议**：hub 增加 `usage/` 旁路目录（Make 只追加自己的使用记录），或打标侧定期合并；供选片降权已用素材。

## P2-9 关键帧留存

- **现状**：每镜头 start/mid/end 三张关键帧 ✓（Make 的视觉去重已直接使用）。
- **建议**：保持并补充：关键帧缩略图（≤320px 宽）单独目录，供未来多模态绑定低成本取用。
